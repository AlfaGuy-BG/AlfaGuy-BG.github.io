Test Case Generator

in production · v4.1

Reads Jira user stories and turns their acceptance criteria into structured Xray test cases, then imports them in bulk.

What it handles
Messy acceptance criteria: nested lists, tables, Gherkin, bilingual text. Pulls in linked issues, subtasks, comments and Confluence pages within a budget. Plans E2E suites across a whole epic.
How it's verified
  • 1,927 automated tests (run of 8 Nov 2026)
  • Snapshot regression: every prompt is hashed, so a code change can't silently change what the AI is asked
  • Rule checks plus an AI judge score every generated case
Guardrails
A secret and ticket-key scan runs before every push. Updates are signed; truncated or wrongly signed packages are refused and failed updates roll back.
Impact
Epic test suites in 5 to 10 minutes instead of days, ~30% less test design effort.

QA Investigation Agent

personal tool

An assistant that does the slow parts of a QA lead's investigations and writes the report with its evidence trail.

Playbooks
  • Coverage gap review: maps every acceptance criterion to test steps, boundaries and AND/OR branches included
  • Client bug trace: one verdict per escaped bug: requirement gap, test design gap, not executed, passed but missed, regression, or not a QA miss
  • Batch analysis: up to 50 bugs at once, then a patterns report with the tests and process fixes worth adding
  • Requirement history: traces a rule back to its original wording, in English and Bulgarian
How it's verified
A red-team harness attacks it with hidden instructions, Unicode smuggling and data exfiltration through links. Web pages are read by a separate quarantined model; after reading one, every change needs a human yes.
Guardrails
Jira and Xray access is read-only by construction. Cleanups never delete: files go to a quarantine with undo.

BuildAnything

experimental

An autonomous improvement loop for any codebase. My QA process, written as software.

How it works
A read-only judge scores the project against the owner's goals with evidence for every finding. Each fix is built in its own branch, tested, and reviewed by the judge before it merges.
How it's verified
The stop rule is plain code, never a model's opinion: done means no open high-severity findings, two clean judge passes and every score above threshold. A planner and an independent challenger argue over every feature before it's built.
Guardrails
A hook blocks pushes, history rewrites, writes outside the work branch and any read of secret files. Every run, item and judge call has a spending cap.

End-of-Day Time Logger

team pilot

A Windows tray app that reminds people to log time and shows every Jira task they touched that day, not only the ones assigned to them.

What it handles
Five task sources merged without duplicates, time typed as 1h30, 1,5 or 90m, Bulgarian public holidays including Orthodox Easter, and a team view for leads.
How it's verified
Tests run in a daylight-saving time zone on purpose. Partial save failures keep their input for retry and are never dropped. Development builds only log what they would send.
Impact
Up to 10 minutes saved per logging session; piloting before an org-wide rollout.

How I work

Rules I wrote into my own projects. They're how I run a QA team too.

Code decides, models propose.

AI can suggest. Whether something is done or allowed is decided by rules a person can read.

BuildAnything working rules
Never silently drop entries.

When part of a job fails, show which part and why, keep the input, retry only that.

Time Logger brief
Nothing is deleted without a way back.

Quarantine before delete. Undo before cleanup. Ask before anything that can't be reversed.

Investigation agent
Readers stay readers.

Whoever reviews the work can't change it. Separation of roles makes the verdict worth something.

BuildAnything working rules
Every run is bounded.

Time, money and scope are capped before work starts, not after it overruns.

BuildAnything working rules
Questions go to the owner, not a guess.

If the answer changes what gets built, ask. If any reasonable answer works, decide and write down why.
